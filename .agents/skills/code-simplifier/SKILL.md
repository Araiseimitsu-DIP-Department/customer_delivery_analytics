# 仕様非変更の整理

変更したコードだけを読み、API・DB・入出力形式を docs と Tests で確認する。
単一責任、共有処理、意味の明確な命名、不要な分岐・重複、1000行制約を点検する。
改善が必要な箇所だけ最小修正する。改善不要ならレビュー済みと報告し、形式的なリファクタリングをしない。
scripts/verify_build.py の依存方針を build_exe.ps1 と二重管理しない。Access 除外が GUI / SQLite / PostgreSQL 依存を巻き込まないか確認する。
全既存テストを実行し、git diff で仕様非変更を確認する。未実施項目は理由を残す。
